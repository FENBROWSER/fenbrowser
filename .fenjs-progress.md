The remaining 2 crashes both traced to the same combination of bugs, fixed together:

1. Object-literal accessors were broken end-to-end. The parser preserved the getter function but `ObjectPropertyNode` had no `Kind` field, so `get foo()` and `foo: function() {}` compiled identically — both went through `SetPropByName`. Reading `o.foo` returned the function instead of invoking it. The spec relies on accessor semantics for `[Symbol.iterator]`, `.next`, etc., so test262 cases that put a getter on an iterator method (case 7 of `errors-iterabletolist-failures.js`) bypassed the protocol's TypeError guards and reached the GC bug below. Fix: `ObjectPropertyKind { Data, Getter, Setter }` on `ObjectPropertyNode`; parser stamps the kind; compiler routes `Getter`/`Setter` through `DefineGetter` / `DefineSetter` (or `DefineGetterByReg` / `DefineSetterByReg` for computed keys).
2. The interpreter held live JsValue Objects in `InterpreterFrame.Registers` that the GC couldn't see. An auto-MinorCollect inside user code could reclaim a cell whose only reachability went through an active frame register. Fix: `JsHeap` grew an `IHeapRootSource` hook; `BytecodeInterpreter` registers itself and maintains a `Stack<InterpreterFrame> _activeFrames`. The GC walks each frame's `Registers`, `ThisValue`, `NewTarget`, `PendingException`, `Environment`. `ActiveFrameScope` (struct + IDisposable) pushes the frame on entry to `ExecuteInternalCore` and pops on every return path via `using` scope semantics.
3. As defense-in-depth, `DrainIteratorIntoList` also temporarily suspends auto-MinorCollect for the drain (CallFunction's freshly allocated return value briefly lives only in a C# local between the callee frame's pop and the caller's store).

6 new `ObjectLiteralAccessorTests` cover the accessor protocol. **2439 main + 40 fuzz green.**
